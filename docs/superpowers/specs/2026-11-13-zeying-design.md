# 择影（selight）设计文档

日期：2026-11-13
状态：待用户批准

## 1. 意图与背景

用户是婚礼摄影师，一次拍摄后要把几百到上千张照片快速过一遍、按类别分好（如合影、仪式、特写、场布），之后自己按类别精修。不同场次（婚礼）之间素材与分类互相独立。

择影是一个本地桌面照片筛选工具。核心价值三条：

1. **快**：键盘为主、拖拽为辅，支持批量操作，适合大批量过片
2. **安全**：原文件只读，永不移动、修改、删除；分类只是数据库里的映射关系，随时可改
3. **可续**：关掉重开能接着上次的现场继续，分类结果持久保存

真实素材基线（来自 `素材/说明.md`）：一场婚礼 1871 张 = 1158 张索尼 ARW + 713 张 JPG，原件约 72G；仓库内的 `素材/` 是同名同目录结构的 webp 轻量副本（最长边 1600px）。ARW 内嵌预览 1616×1080 且**不带方向标记**，其中 572 张竖拍（EXIF 6 共 204 张、EXIF 8 共 368 张）必须按 EXIF Orientation 转正，否则约 30% 照片横置。

## 2. 目标、非目标、反目标

### 目标（v1）

- 以「批次」组织工作：每次新拍摄开一个批次，待分类池、文件夹、回收站全部按批次隔离；工具栏可切换历史批次
- 选择源文件夹导入到当前批次，递归扫描所有受支持照片并建索引
- 三栏主界面：左栏待分类缩略图、中间大图预览、右栏文件夹卡片 + 回收站卡片
- 照片通过拖拽或快捷键分配到文件夹；分配后从待分类池消失
- 文件夹可新建、改名、删除；删除文件夹时其中照片回到待分类池，不丢照片
- 回收站是特殊分类（不是真删除），照片可恢复到原文件夹
- 文件夹内可二次筛选：把分错的照片挪到别的文件夹或扔进回收站
- 批量选择（Ctrl/Shift 多选）后批量分配；一次批量分配在撤销时算一步
- 完整撤销：分配、扔回收站、恢复、删文件夹均可 Ctrl+Z，重启后仍可撤销
- EXIF 方向自动转正：旋转烘焙进缩略图/预览缓存，界面层不做旋转
- 状态持久化，重开应用恢复全部现场（含上次所在批次和视图）
- 导出：按文件夹把照片**复制**到用户选择的输出目录（原文件不动），每个文件夹生成同名子目录
- 支持 JPG/JPEG/PNG/WEBP 直读；RAW（ARW/CR2/CR3/NEF/DNG/RAF/RW2/ORF/PEF/SRW）显示内嵌 JPG 预览
- 视觉：现代 macOS 系统应用风格（浅色），应用运行在 Windows 上，使用系统原生窗口框，内部 UI 采用 macOS 视觉语言

### 非目标（v1 不做）

- 不修图、不做任何图像编辑
- 不做星级、标签、颜色标记
- 不做深色模式
- 不做云同步、多机协作、多人功能
- 不做 AI/人脸自动分类
- 不支持视频
- 不做列表视图、搜索框（草图里出现过，v1 只保留缩略图网格；后续需要再加）
- 不做照片物理移动，应用内一切操作只改数据库
- 不做跨批次合并、批次删除/归档管理 UI（批次只增不删，旧批次可随时回看）

### 反目标（做到了就算失败）

- 任何对原文件的写入、移动、重命名或删除
- 分类数据丢失或无法恢复（含删文件夹、删照片记录等误操作路径）
- 竖拍照片在界面里横置
- 2000 张规模下界面卡顿、缩略图加载阻塞操作

## 3. 用户工作流

1. 新建批次（默认名称=日期，可改），点「导入文件夹」选择源目录（可多次导入、可递归子目录）。应用扫描照片、建索引、后台生成缩略图和 RAW 预览（含方向转正）
2. 左栏显示当前批次的全部**待分类**照片（两列缩略图网格），中间显示当前选中照片的大图
3. 用户看图后：把照片拖到右栏某张文件夹卡片，或按数字快捷键分配；照片立即从待分类池消失，对应文件夹卡片张数 +1
4. 不要的照片拖到回收站卡片（或按 Delete）
5. Ctrl/Shift 多选后可一次分配多张
6. 点文件夹卡片 → 左栏切换为该文件夹内容（顶部出现返回入口），可把照片拖到别的卡片或回收站做二次筛选
7. 点回收站卡片 → 左栏显示回收站内容，可拖回或点「恢复」回到原文件夹（原文件夹已删除则回到待分类池）
8. 全部过完后，点「导出」选择输出目录，应用按文件夹复制照片，拿去精修
9. 下一场拍摄：新建批次，现场与旧批次完全隔离；工具栏下拉可切回任意历史批次
10. 中途关掉应用，下次打开恢复：上次批次、待分类池、各文件夹、回收站、导入来源、当前视图都在

重复导入同一源文件夹时：按「批次 + 绝对路径」识别，已存在的跳过，mtime/size 变化则刷新元数据；磁盘上已不存在的文件标记为「丢失」（缩略图上加标记，不自动删除记录）。

## 4. 界面规格

整体为三栏 + 顶部工具栏，无应用内假标题栏（窗口框由操作系统提供）。视觉语言对齐现代 macOS 系统应用（访达/照片）：

- 字体：-apple-system / SF Pro 栈，Windows 上回退 Segoe UI
- 色板：主文字 #1D1D1F，次要文字 #6E6E73/#86868B，分隔线 0.5px 半透明黑，侧栏毛玻璃质感材质，系统蓝 #007AFF（选中/主操作），系统红 #FF3B30（回收站），系统橙 #FF9500（批量多选角标）
- 全部图标使用 SF Symbols 风格的单色线性 SVG，禁止 emoji 图标
- 只做浅色

### 4.1 工具栏

- 批次下拉选择器（显示当前批次名，可切换历史批次）+「新建批次」
- 「导入文件夹」按钮（macOS 圆角按钮样式）
- 「导出」按钮
- 右侧：进度文字「已分 X / 共 Y」+ 系统蓝细进度条（均按当前批次统计）

### 4.2 左栏（宽度约 200px，毛玻璃材质）

- 待分类视图：标题「待分类」+ 剩余张数
- 文件夹视图：标题为文件夹名 + 张数，顶部有返回按钮回到待分类
- 回收站视图：标题「回收站」+ 张数
- 两列缩略图网格，圆角 5px、轻投影；选中照片显示 macOS 照片 App 同款蓝色圆形对勾角标，批量多选的其余照片为橙色角标
- 丢失文件的缩略图右下角加灰色警告角标，预览区提示文件不可用
- 滚动虚拟化（2000+ 张时只渲染可见区域）
- 缩略图按需生成，可见区域优先
- 排序：默认按文件路径+文件名排序（ORDER BY 成本低，后续可加排序选项）

### 4.3 中间预览区

- 大图居中 contain 显示（已转正），左右两侧半透明圆形翻页箭头
- 底部信息条：文件名、尺寸、文件大小；快捷键提示
- 键盘 ← → 切换上一张/下一张（在当前左栏视图范围内）

### 4.4 右栏（宽度约 264px，毛玻璃材质）

- 标题「文件夹」+ 加号图标按钮
- 两列文件夹大卡片网格：访达风格实心文件夹图形（选中反白）+ 名称 + 「N 张」
  - 选中（当前左栏正在浏览的文件夹）：系统蓝实心卡片
  - 拖拽悬停：蓝色虚线描边
- 「新建文件夹」为虚线占位卡片，点击后行内输入名称（Enter 确认/Esc 取消）
- 文件夹卡片右键菜单：改名（行内编辑）、删除（确认对话框，提示照片将回到待分类）
- 回收站卡片固定在网格底部、独占整行，红色调；拖拽悬停红色虚线描边
- 文件夹/照片过多时右栏内部滚动
- 文件夹超过 9 个时数字快捷键只覆盖前 9 个，其余靠拖拽

### 4.5 快捷键（v1 方案，不做自定义）

| 按键 | 动作 |
|---|---|
| ← →（或 ↑ ↓） | 切换选中照片 |
| 1–9 | 把选中照片分配给第 N 个文件夹 |
| Delete / Backspace | 扔进回收站 |
| Ctrl+Z | 撤销最近一次动作（批量分配整批一步撤） |
| Esc | 从文件夹/回收站视图返回待分类 |
| Ctrl/Shift+点击 | 多选；Ctrl+A 全选当前视图 |

行内编辑（新建/改名文件夹）聚焦时，Delete、Ctrl+Z 等全局快捷键让位于输入框。

## 5. 数据模型

SQLite 数据库，位于系统应用数据目录 `userData/selight.db`。

```
batches          批次（一场拍摄一个）
  id, name, created_at, last_opened_at

sources          导入来源（属于某个批次）
  id, batch_id, abs_path, imported_at, last_scan_at
  UNIQUE(batch_id, abs_path)

folders          用户文件夹（回收站是虚拟分类，不在此表）
  id, batch_id, name, sort_order, created_at, deleted_at(软删)
  UNIQUE(batch_id, name) WHERE deleted_at IS NULL

photos
  id, batch_id, source_id, abs_path, filename, ext,
  size_bytes, mtime, width, height,
  orientation,         -- EXIF 方向值 1/3/6/8，默认 1
  thumb_path,          -- userData 下缓存缩略图的相对路径（已转正）
  preview_path,        -- RAW 内嵌预览缓存路径（已转正）；JPG/WEBP 为空
  status,              -- 'inbox' | 'folder' | 'trash'
  folder_id NULLABLE,  -- status=folder 指向 folders.id；trash 时记录原文件夹用于恢复
  missing INTEGER DEFAULT 0,  -- 磁盘文件已不存在
  created_at, updated_at
  UNIQUE(batch_id, abs_path)

actions          分类动作日志，用于撤销
  id, batch_id, batch_id_group,  -- batch_id_group：同一次批量操作共享，单张操作也独占一组
  photo_id, from_status, from_folder_id,
  to_status, to_folder_id,
  undone INTEGER DEFAULT 0, created_at
```

关键规则：

- 分配/扔回收站/恢复：写 photos 新状态 + 追加一条 action，单事务；同一次批量操作的所有 action 共享 `batch_id_group`，撤销按组整批回滚
- 删文件夹：文件夹软删；其下 photos 全部回到 inbox，每照片写 action（同组）。撤销该组时连带复活文件夹（恢复名称与 sort_order）
- 回收站恢复：folder_id 指向的原文件夹存在（未软删）则回原文件夹，否则回 inbox；恢复本身也写 action，可再撤销
- 撤销：取最近一个未撤销组，组内每张照片恢复 from_* 状态，置 undone=1；涉及软删文件夹的组同时复活/重新软删文件夹
- action 日志持久化、重启后仍可撤销，v1 不做日志截断
- 切换批次只是查询条件变化，所有表按 batch_id 隔离
- 导出不改变任何状态

## 6. 技术方案（builder 的决定，记录在案）

- **Electron + React + TypeScript + Vite**，本地桌面应用
- 数据访问：**better-sqlite3**（同步 API、零外部依赖、事务简单可靠）
- RAW 内嵌预览与方向：**exiftool-vendored**（自带各平台 exiftool 二进制，离线可用），提取 ThumbnailImage/PreviewImage 与 Orientation；预览图按 Orientation 旋转后缓存到 `userData/previews/`，orientation 原值入库
- 缩略图：Electron 内置 `nativeImage.createThumbnail` 缩放，按 orientation 转正后缓存到 `userData/thumbnails/`，不引入 sharp 等额外原生依赖
- JPG/WEBP 等直读格式：Chromium 本身遵守 EXIF 方向自动转正；缩略图同样按 orientation 烘焙，保证两条管线观感一致
- 大图：通过自定义安全 protocol 读取本地文件；RAW 读缓存的内嵌预览
- 扫描与缩略图生成在主进程队列中后台执行，按可见优先级调度；渲染进程虚拟化网格（react-window 一类轻量库）
- 拖拽：HTML5 Drag and Drop（Electron Chromium 原生支持）
- 测试：Vitest 单测覆盖分类核心逻辑（批次隔离、分配、回收站、恢复、删文件夹、分组撤销、重复导入、方向值映射）；真实样本冒烟（见下）
- 打包：electron-builder，先出 Windows 安装包

### 真实样本验证

用户将提供 3–5 张真实样本（含竖拍 ARW 和普通 JPG），放入仓库 `samples/`（加入打包忽略，不进安装包）。冒烟用例：ARW 内嵌预览提取、EXIF 6/8 两个方向的转正结果、JPG 直读、缩略图与大图方向一致性。在此之前用 `素材/` 的 1871 张 webp 做全流程开发自测。

## 7. 导出规格

- 工具栏「导出」→ 选择输出目录 → 进度对话框（按当前批次）
- 每个非空文件夹生成同名子目录，把其中照片的**原文件复制**进去（RAW 复制原 RAW，不复制预览图；按 photos.abs_path 找原件）
- 回收站内容不导出
- 文件名冲突时加 `(1)`、`(2)` 后缀，不覆盖
- 复制用 Node fs，带进度（已复制/总字节），完成后可点「在资源管理器中打开」

## 8. 边界与错误处理

- 源目录无受支持照片：空状态提示
- 文件权限/磁盘错误：单文件失败不中断整批，结束后给出失败清单
- 数据库损坏：启动时检测，损坏则备份后重建并提示重新导入（分类映射会丢，原文件不受影响）
- 照片在磁盘上被移动/删除：标记 missing，缩略图仍可见但预览区提示文件不可用，不自动清记录
- 文件夹重名：同批次内新建/改名时拦截并提示
- 大体积 RAW 提取预览慢：队列异步，界面先显示占位卡，提取完再替换
- exiftool 提取失败：该照片用文件类型占位缩略图并标记，不阻断整批扫描

## 10. 已确认的决策记录

- 原文件零改动，分类存数据库（用户确认）
- 分完即从左栏待分类池消失（用户确认）
- 重开应用恢复现场（用户确认）
- 需要批量多选操作（用户确认）
- 二次筛选只做挪文件夹/扔回收站，不做星级标签（用户确认）
- macOS 风格、只做浅色、无假窗口外壳、单色线性图标、文件夹大卡片（用户确认）
- JPG 直读 + RAW 内嵌预览（用户确认）
- 点文件夹卡片后左栏切换显示其内容（用户确认）
- 导出为复制到新目录（用户确认）
- 文件夹可改名可删除，删除后照片回待分类（用户确认）
- 回收站恢复回原文件夹（用户确认）
- 多场次用批次隔离，同一数据库内切换（用户确认）
- 用户提供真实 ARW/JPG 样本用于 RAW 管线验证（用户确认）
- EXIF 方向烘焙进缓存、批量分配整组撤销、删文件夹可撤销、重启后可撤销（builder 依据素材说明与审查意见决定）
